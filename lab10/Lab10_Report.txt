2. Hardware Utilization:
Look at the output of your Live Dashboard. Explain how the OS successfully ran Workload A (LLaMA Training), Workload B (Preprocessing), and Workload C (Inference) AT THE SAME TIME without crashing. Why didn't they block each other?

Explanation:
The OS scheduler analyzed resource requirements and matched non-overlapping hardware demands:
1. Workload A allocated 40GB RAM and GPUs [0, 1, 2].
2. Workload B required 16GB RAM and 0 GPUs. Because 24GB RAM remained free and Workload B required zero GPUs, the OS dispatched Workload B to run on CPU threads in parallel with Workload A.
3. Workload C needed only 2GB RAM and 1 GPU. With 8GB RAM remaining and GPU 3 idle, Workload C acquired GPU 3 and executed without interfering with Workload A or B.
Because the OS independently manages distinct resource locks (RAM vs individual GPU devices), workloads only block when competing for the exact same resource.

1. Race Condition:
The third experiment demonstrated a race condition by creating two threads
that updated the same shared weight. Each update required three steps: read
the value, add one, and write the result. Because both threads could read the
same value, one update could overwrite the other. The expected value was 200,
but the actual value was 101. The short `time.sleep(0.0000001)` made it easier
for the scheduler to switch threads between the read and write operations.

2. Producer-Consumer Synchronization:
The next experiment implemented a producer-consumer system with a bounded
buffer. The producer loaded image batches into the buffer, while the
consumer removed them for GPU training. The `mutex` allowed only one thread
at a time to change the buffer and its indexes. The `empty` semaphore counted
available buffer slots, and the `full` semaphore counted items ready for the
consumer. This showed why a mutex alone cannot replace the semaphores: a
mutex controls access, but it does not count resources.

3. Deadlock Awareness:
The experiment also demonstrated how incorrect lock ordering can cause a
deadlock. If the producer acquired the `mutex` while the buffer was full and
then waited for an empty slot, the consumer could not acquire the mutex to
remove an item. Acquiring `empty` before the mutex allows the producer to
wait without blocking the consumer.

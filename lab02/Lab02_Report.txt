1. Experiment Setup:
The second experiment compared three ways to process 16 simulated images.
The `task.py` program performed a heavy mathematical loop for each image to
simulate CPU-intensive work, such as an ML data augmentation task.

2. Execution Time Comparison:
First, `runner_seq.py` processed the images one at a time and took 8.93
seconds. Next, `runner_thread.py` created 16 threads and took 8.73 seconds,
which was only slightly faster than the sequential method.

Finally, `runner_process.py` created 16 separate operating system processes.
This method took 7.71 seconds and was the fastest. The `htop` observation
showed that multiprocessing used the two logical CPUs more effectively.

3. Analysis of the GIL:
The similar sequential and multithreading times were caused by Python's GIL,
which allows only one thread to execute Python code at a time within a
process. Multiprocessing performed better because each process has its own
Python interpreter and GIL, allowing CPU-intensive work to run on more than
one CPU core.
